# 入库前抽象工作流

## 适用场景

当原始资料有价值，但不适合直接进入用户可检索知识库时，使用本工作流。

典型资料包括：

- 往届学生作业、报告、论文或课堂展示。
- 客户案例、内部复盘、项目交付件。
- 会议纪要、访谈材料、调研记录。
- 带有个人表达、隐私、版权、临时结论或历史版本语境的资料。

这些资料通常不应直接上传给智能体检索，但可以抽象出方法论、规范、检查清单、主题地图、常见问题和优秀实践。

## 核心原则

```text
原始资料
  -> 入库前处理区
  -> 结构化摘要
  -> 抽象方法论
  -> 人工审核
  -> 正式知识库
  -> 智能体提示词与测试同步更新
```

入库前处理区不是最终知识库。它只是加工车间。真正要让智能体使用，必须把审核后的抽象材料移入正式上传目录，并更新上传清单、提示词和测试问题。

## 目录建议

```text
knowledge_base/
  _pre_ingestion/
    <source_batch>/
      README.md
      source_inventory.md
      item_digests/
      theme_map.md
      candidate_kb_entries/
  stable_materials/
    <domain>/
      <abstracted_methodology>/
  policy_and_boundaries/
  _manifests/
```

`_pre_ingestion/` 默认不上传。`stable_materials/<domain>/<abstracted_methodology>/` 才是审核后可上传的正式目录。

## 第一步：原始资料归档

保留原始资料，但不要直接上传到智能体知识库。记录资料来源、时间、权限、文件类型、是否含个人信息、是否有版权或合规风险。

建议生成 `source_inventory.md`，至少包含：

- 原始文件名。
- 资料类型。
- 来源和时间。
- 是否含个人信息。
- 是否可公开。
- 预期抽象价值。

## 第二步：结构化摘要

为每份资料生成一张摘要卡片。摘要卡片用于维护者审核，不直接上传。

推荐字段：

```yaml
---
kb_type: pre_ingestion_digest
source: <source batch>
risk_level: medium
review_status: pending
upload_to_agent_kb: false
---
```

推荐内容：

- 原始资料位置。
- 核心主题。
- 可复用价值。
- 需要谨慎的内容。
- 可抽象出的规范、方法或检查清单。
- 是否建议进入正式知识库。

摘要卡片不要保留可直接复制的完整正文、个人化表达或敏感内容。

## 第三步：主题地图

把一批资料聚类为主题地图。主题地图用于回答“这批资料整体能沉淀什么”，而不是罗列历史作品。

可按以下维度整理：

- 主题分布。
- 写作类型或业务类型。
- 常见方法。
- 常见错误。
- 可沉淀为正式知识库的方向。
- 不应进入正式知识库的内容。

## 第四步：抽象为候选知识条目

从摘要和主题地图中提炼候选条目。候选条目应脱离原始资料语境，转化为可复用知识。

常见抽象类型：

- 写作规范。
- 操作流程。
- 主题选择方法。
- 问题形成方法。
- 质量检查清单。
- 常见误区与边界。
- 工具或方法的适用场景。

候选条目仍应保持：

```yaml
review_status: pending
upload_to_agent_kb: false
```

## 第五步：人工审核并转为正式知识库

只有通过审核的抽象条目才进入正式知识库目录。

转入正式目录时，需要：

- 改写掉残留的个人表达。
- 删除历史个案中不可公开的信息。
- 明确适用范围和边界。
- 加入 YAML 元信息。
- 将 `upload_to_agent_kb` 改为 `true`。
- 放入上传清单。

## 第六步：同步智能体行为协议

如果新增资料会改变智能体能力或边界，必须更新系统提示词或行为协议。

常见更新包括：

- 告诉智能体新增了哪类抽象知识。
- 告诉智能体哪些原始资料仍然不能提供。
- 规定回答方式：给方法、结构、检查清单，不给可直接提交的完整作品。
- 增加拒答或转向回答模板。

## 第七步：更新测试问题

新增抽象知识后，至少补充三类测试：

- 正向测试：智能体能否使用新方法论回答问题。
- 边界测试：智能体是否拒绝提供原始资料、范文、敏感内容或完整提交件。
- 检索测试：智能体能否说明哪些目录上传、哪些目录不上传。

## 常见错误

- 只做 `_pre_ingestion/`，但忘记把审核后的抽象条目放进正式知识库。
- 把原始资料或逐份摘要上传给用户可见知识库。
- 抽象条目仍保留太多原作品结构，导致用户可以模仿提交。
- 上传知识库后忘记更新提示词，智能体不知道如何使用新资料。
- 更新提示词后忘记新增回归测试，后续维护时边界退化。

## 完成标准

本工作流完成时，应能回答：

- 哪些原始资料被处理了？
- 哪些内容留在入库前处理区，且不会上传？
- 哪些抽象条目进入正式知识库？
- 上传清单是否包含正式目录并排除处理区？
- 智能体提示词是否知道新资料的使用方式和边界？
- 测试问题是否覆盖新增能力和边界？
