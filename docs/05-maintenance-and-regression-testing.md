# 维护与回归测试

## 维护闭环

每次更新都应形成闭环：

```text
更新本地知识库
  -> 更新上传清单
  -> 同步到平台知识库
  -> 确认索引完成
  -> 更新系统提示词
  -> 发布应用
  -> 新会话测试
  -> 填写测试记录
  -> 填写更新记录
```

## 最小回归测试

核心回归问题应覆盖：

- 高频事实
- 高风险事实
- 同义词问法
- 知识库没有答案的问题
- 边界拒答
- 领域专业能力
- 引用或依据说明

## 测试记录

建议记录：

```markdown
## 测试日期

## 测试平台

## 知识库版本

## 系统提示词版本

## 测试问题与结果

| 编号 | 问题 | 预期要点 | 实际结果 | 通过 | 备注 |
| --- | --- | --- | --- | --- | --- |

## 结论
```

## 更新记录

建议记录：

```markdown
## 日期

- 更新原因：
- 修改文件：
- 是否同步平台：
- 是否完成索引：
- 是否更新系统提示词：
- 回归测试结论：
- 后续待办：
```

## 常见失败点

- 本地提示词改了，但平台仍使用旧提示词。
- 文件上传了，但索引未完成。
- 应用没有绑定正确知识库。
- 旧文件没有删除，导致新旧事实冲突。
- 核心事实只写在长文档里，检索不稳定。
- 测试使用旧会话，缓存了旧上下文。

## 完成标准

一次更新完成时，应同时满足：

- 本地知识库已更新。
- 上传清单与实际上传一致。
- 平台知识库已同步并索引。
- 系统提示词已发布。
- 核心回归测试通过。
- 更新记录和测试记录已填写。
