# 从课程智能体到通用智能体

## 特定课程智能体

特定课程智能体关注一个具体课程：

- 课程时间地点
- 任课教师
- 阅读材料
- 评分方式
- 作业和论文要求
- 课程知识点
- 学术诚信边界

## 通用课程智能体

去掉具体课程内容后，所有课程智能体共享结构：

```text
课程事实
学习资料
作业/论文/项目要求
学术诚信边界
每学期更新流程
核心回归测试
```

## 通用智能体

再往上抽象，课程只是领域之一。任何知识库智能体都需要：

```text
领域事实
稳定资料
边界政策
意图映射
行为协议
发布清单
测试问题
维护记录
```

## 可迁移的判断问题

创建任何智能体前，先回答：

1. 它服务谁？
2. 用户最常问什么？
3. 哪些信息答错风险最高？
4. 哪些资料可以进入用户知识库？
5. 哪些资料只能留给维护者？
6. 没有资料时应该怎么说？
7. 哪些请求必须拒绝？
8. 每次更新后如何测试？
9. 谁负责维护？
10. 如何判断线上配置已经生效？

这些问题比选模型更早，也更重要。
