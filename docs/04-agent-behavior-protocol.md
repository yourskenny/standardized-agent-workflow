# 智能体行为协议

系统提示词应被视为智能体的行为协议，而不只是角色设定。

## 推荐结构

```markdown
# 系统提示词

## 一、身份与服务对象
## 二、任务范围
## 三、知识库范围
## 四、回答优先级
## 五、核心事实
## 六、意图识别与问法归一化
## 七、高风险问题处理
## 八、边界与拒答
## 九、回答风格
## 十、推荐回答模板
```

## 回答优先级

推荐使用明确顺序：

1. 系统提示词中的核心事实。
2. 知识库中的核心事实文件。
3. 正式来源文档。
4. 领域学习资料。
5. 通用知识。

如果通用知识与项目资料冲突，以项目资料为准。

## 高风险问题

在提示词中明确列出高风险问题类型。

示例：

```markdown
遇到截止日期、费用、评分、提交方式、权限、法律、医疗、安全、个人隐私等高风险信息时，必须优先依据知识库。若知识库没有明确说明，直接说明没有找到依据，不要猜测。
```

## 没有依据时的标准回答

建议固定为：

```text
根据目前知识库资料，我没有找到关于这个问题的明确说明。建议向负责人确认。
```

## 拒答不是终止帮助

拒绝高风险或不合规请求后，应转向允许的帮助方式。

示例：

```text
我不能直接替你完成完整提交件，但可以帮你拆解任务、整理结构、检查思路，并提供示例片段。
```

## 意图映射

用户往往不会使用正式术语。系统提示词和知识库中都应写清映射。

示例：

```markdown
- “ddl” = 截止时间
- “找谁问” = 负责人或联系方式
- “能不能补” = 补交或例外政策
```

## 禁止输出的已知错误

如果项目中曾出现稳定幻觉，应把错误写入提示词。

示例：

```markdown
严禁输出以下错误信息：...
```

这不是为了让提示词背锅，而是为高频错误加防护栏。
